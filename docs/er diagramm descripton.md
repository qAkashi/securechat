1. Сущность USER (Пользователь / Участник сессии)
Хранит данные о подключившихся пользователях и их публичных ключах, необходимых для инициализации E2EE.

user_id (String, PK) — уникальный идентификатор пользователя (генерируется на клиенте или сервере).

username (String) — псевдоним пользователя.

public_key (Text) — публичный RSA-ключ пользователя, который отправляется другим участникам для шифрования сообщений.

created_at (Timestamp) — время создания сессии.

2. Сущность CHAT_ROOM (Приватная комната)
Определяет изолированные пространства для общения.

room_id (String, PK) — внутренний ID комнаты.

room_code (String, Unique) — 6-значный код доступа, по которому другие пользователи находят комнату.

created_at (Timestamp) — время создания комнаты.

expires_at (Timestamp) — время автоматического уничтожения комнаты (для обеспечения концепции нулевого следа).

3. Сущность ROOM_PARTICIPANT (Участники комнат)
Связующая таблица (многие-ко-многим) для отслеживания того, какие пользователи в каких комнатах находятся в данный момент.

participant_id (String, PK) — уникальный ID записи.

room_id (String, FK) — идентификатор комнаты.

user_id (String, FK) — идентификатор пользователя.

joined_at (Timestamp) — время входа в чат.

4. Сущность ENCRYPTED_MESSAGE (Зашифрованное сообщение)
Даже если сообщения не сохраняются на диске, в архитектуре WebSocket-сервера эта структура описывает пакет данных, транслируемый между клиентами.

message_id (String, PK) — ID сообщения.

room_id (String, FK) — в какую комнату отправлено.

sender_id (String, FK) — кто отправил (ссылка на USER).

encrypted_content (Text) — текст сообщения, зашифрованный на клиенте алгоритмом AES-256. Сервер не может его прочитать.

iv_vector (String) — вектор инициализации (Initialization Vector), необходимый клиенту для корректного дешифрования алгоритма AES.

timestamp (Timestamp) — время отправки.

Связи между сущностями (Кардинальность):
Один Пользователь (USER) может состоять в нескольких Комнатах (CHAT_ROOM) одновременно, и в одной комнате может быть много пользователей. Связь реализуется через таблицу ROOM_PARTICIPANT как 1:N и 1:N.

Один Пользователь может отправить множество Сообщений (ENCRYPTED_MESSAGE) — связь 1:N.

Одна Комната может содержать множество Сообщений — связь 1:N.
